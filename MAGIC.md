# MAGIC.md — ae3.sdk

Team-owned. Durable findings/gotchas for this repo, not investigation narration.

## For keeper-ae3

- **A malformed Basic credential is refused inside `ru.myx.auth.AuthUtils.squeezeCredentialsFromRequestHeaders`.** `ru.myx.util.Base64.decode` throws `RuntimeException("Decoder error: Invalid base64 encoding.")` when the payload length is not a multiple of four, so the decode sits in a try/catch there and throws `Reply.exception(Reply.stringUnauthorized("AUTH:BASIC", query, "Invalid credentials"))`. The answer is a 401 carrying `WWW-Authenticate: Basic realm="sign in"` and a plain `Invalid credentials` body, never a 500 with a dump (MAGIC-11, the MAGIC-8 trigger).
- **`AbstractReplyException` is the platform's handled-refusal carrier.** It is an `ExecNonMaskedException`, so the VM and the JS layer pass it through unnested, and `WebTargetActor.apply` sends its `getReply()` as the answer. An input-reading site refuses by throwing one; no new exception kind is needed.
- **`Context.checkAuthorization` (acm-base-api) swallows a 401 or 403 reply exception** and then throws its own sign-in challenge, so an ACM-side caller sees the standard 401 either way.
- **A source edit reaches the local rig only after its class is recompiled** into the project's own `bin/` tree, which the rig puts on its classpath: `javac -cp <every ae3.*/clean-* bin> -d /Volumes/workspace/myx/ae3.sdk/bin <file>`.
- **The regression test is the `auth` subsystem test**: `/Users/myx/Workspaces/ws-myx.ae3-devel/source/ae3/ae3.test/java/ru/myx/ae3/test/auth/TestAuth.java`, registered as `/Users/myx/Workspaces/ws-myx.ae3-devel/source/ae3/ae3.test/ae3-packages/ae3.test/settings/tests/auth.json` and called from `/Users/myx/Workspaces/ws-myx.ae3-devel/source/ae3/ae3.test/java/ru/myx/ae3/test/TestAe3.java`. Run it with `java -ea`, every project's `bin/` and the axiom jars on the classpath.
- **The credential parser is reachable over HTTP only where a share calls it.** `Ae3WebService` overrides `onHandle`, so `ae3.local` never runs its authentication provider and answers 200 to a malformed header. The live caller is `Context.checkAuthorization`, which the local rig does not load. A probe share calling `ru.myx.auth.AuthUtils.squeezeCredentials` gives the signal: 401 with the sign-in challenge and a 19-byte body on this code, 500 with a 21,648-byte dump on the unguarded version. JS reaches the parser through `require("java.class/ru.myx.auth.AuthUtils")`, as `/Volumes/workspace/myx/acm-cvs/sys-current/resources/lib/ae3.util/Auth.js` does.
- **Backtick template literals compile by lexer desugar, not by an engine token.** `ExpressionParser` lexes `` `…${expr}…` `` through its own states (`ST_TEMPLATE`, `ST_3STRING_FUNCTION_ROOT`, `ST_3STRING_FUNCTION_ACCS`, `ST_3STRING_FUNCTION_NEW`), then emits the ordinary string `+` sequence (`java/ru/myx/ae3/eval/parse/ExpressionParser.java:111-117`, `:3084`). Neither project has a template token, instruction or operation. The desugar uses `baseToJavaString` (ToPrimitive default), not the template-literal ToString hint. Every template therefore runs the string-concat path below.
- **A string `+` chain compiles to `TKV_MADDS_BA_VV_S` and concatenates pairwise, without the string cache.** `TKO_MADD_*_BA_SS_S.toStackValue` folds `"" + x` away and lets a constant pair fold in `super.toStackValue`. A string operand then yields `TKV_MADDS_BA_VV_S`; numeric operands alone yield `TKV_MADDN_BA_VV_S` (`java/ru/myx/ae3/eval/parse/TKO_MADD_D_BA_SS_S.java:118-176`). `TKV_MADDS_BA_VV_S.toAssembly` feeds both operands through `ResultHandler.FS_BSN_NXT`/`FS_BNN_NXT`, never the caching `FB_BSN_NXT`/`FA_BNN_NXT` (`java/ru/myx/ae3/eval/parse/TKV_MADDS_BA_VV_S.java:80-96`). Runtime add is plain Java `+`: `argumentA.baseToJavaString() + argumentB.baseToJavaString()` (`java/ru/myx/ae3/exec/OperationsS2X.java:703-760`). No N-ary single-buffer join exists, so a long template allocates one `String` per piece.
- **`EFS_BSN_NXT` is the live non-caching string stack handler.** It extends `ResultHandlerBasic` and sends string results to `ExecProcess.vmSetResultVmStackString`, which keeps them as raw `ValueStackString` instead of `CACHE_STR.cacheGetCreate` (`/Volumes/workspace/myx/ae3.api/java/ru/myx/ae3/exec/EFS_BSN_NXT.java`). It is reached only through `ResultHandler.FS_BSN_NXT` (`/Volumes/workspace/myx/ae3.api/java/ru/myx/ae3/exec/ResultHandler.java:570`). Before commit `2767daf` the class was unreferenced.
- **The `store ==` comparisons in `TKO_MADD_*_BA_SS_S` are not the string-concat node.** They compare `ResultHandler.FA_BNN_NXT`/`FB_BSN_NXT` only to pick an instruction variant for the general `+` operator, whose result is OBJECT, string or number (`java/ru/myx/ae3/eval/parse/TKO_MADD_D_BA_SS_S.java:83-99`). Editing them does not change string caching.
- **N-ary stack operations carry their count in the `constant` slot.** `TKV_CARRAYX_ON_STACK` pushes N operands, then one `OperationsA00.XCARRAY_N` carries N (`java/ru/myx/ae3/eval/parse/TKV_CARRAYX_ON_STACK.java`, `java/ru/myx/ae3/exec/OperationsA00.java:18`). An operation holds about three fixed operands at most (`OperationsA3X`), so a many-operand operation is built this way.
- **The eval suite is not green in this tree, and was not before the concat change.** Three known failures: `TestEvalExpression` around line 262 (object tag `[object BaseNativeObject]` where `[object Object]` is expected), `TestEvalParseTokens`, and `TestEvalOptimiser` (`InstructionCount: expected 4, but 1`). Run the suite per `/Volumes/workspace/myx/ae3.test/MAGIC.md`.
